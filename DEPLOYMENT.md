# Инструкция по деплою

## Настройка CSR (Client-Side Rendering)

Приложение настроено для работы в режиме CSR (Client-Side Rendering). При сборке создается статический экспорт в папке `out/`, который можно задеплоить на любой статический хостинг.

### Сборка проекта

```bash
npm run build
```

После сборки статические файлы будут находиться в папке `out/`.

## Настройка GitHub Actions для автоматического деплоя

### GitHub Pages (настроено)

Workflows уже настроены для деплоя на GitHub Pages с кастомными доменами:

- **Dev версия** (ветка `develop`) → деплоится в ветку `gh-pages-dev` → `dev.hodleague.com`
- **Production версия** (ветка `master/main`) → деплоится в ветку `gh-pages` → `hodleague.com`

### Настройка кастомных доменов в GitHub Pages

1. **Для Production (hodleague.com):**
   - Перейдите в **Settings → Pages**
   - В разделе **Source** выберите ветку `gh-pages` и папку `/ (root)`
   - В разделе **Custom domain** введите `hodleague.com`
   - Сохраните настройки
   - GitHub создаст файл `CNAME` в ветке `gh-pages`

2. **Для Dev (dev.hodleague.com):**
   - GitHub Pages не поддерживает несколько веток для одного репозитория напрямую
   - **Вариант А:** Используйте отдельный репозиторий для dev окружения
   - **Вариант Б:** Настройте поддомен через DNS и используйте отдельный репозиторий или другой хостинг для dev

### Настройка DNS для поддомена dev.hodleague.com

Если вы хотите использовать поддомен `dev.hodleague.com`:

1. В настройках вашего DNS провайдера добавьте CNAME запись:
   - **Имя:** `dev`
   - **Тип:** `CNAME`
   - **Значение:** `ruddch.github.io`

2. После деплоя dev версии, GitHub автоматически определит поддомен

**Альтернативное решение:** Используйте отдельный репозиторий `hodl-dev` для dev окружения и настройте его на `dev.hodleague.com`

### Альтернативные варианты деплоя

Если вы хотите использовать другой хостинг, вы можете изменить workflow файлы. Примеры других вариантов (SSH, Vercel, Netlify) можно найти в комментариях в workflow файлах.

## Ветки и окружения

- **develop** → автоматически деплоится на dev домен при пуше
- **master/main** → автоматически деплоится на production домен при пуше

## Ручной запуск деплоя

Оба workflow можно запустить вручную через GitHub Actions интерфейс (кнопка "Run workflow").
